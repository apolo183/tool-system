# P14H Multi-Stack Fixture Acceptance

`P14H_ACCEPTED_ISOLATED_MULTI_STACK_FIXTURES_ONLY`

## Accepted evidence

The Python fixture proves repository-context selection, deterministic blueprint
compilation, an existing-library change, a greenfield CLI addition, one bounded
repair cycle after source passes but status remains stale, independent review,
and one remote-free durable local Git commit. The TypeScript fixture proves the
same language-neutral route with an exact add/modify/delete topology and local
Node syntax validation.

Negative and recovery scenarios prove ambiguous blueprint and invented
milestone blocking, atomic out-of-scope rejection before a branch exists,
caller cancellation with unapplied-patch discard and resume, repeated-state
termination, non-blocking suggestions, evidence non-reopening for stale PR
metadata, completed-commit crash resume without a duplicate task/branch/commit
or remote PR, and existing-branch conflict blocking.

## Evidence boundary

All repositories, Git branches, commits, SQLite stores, callbacks, Python code,
and TypeScript code are isolated pytest fixtures. Remote Git/GitHub fixture
operations, provider calls, credential reads, downstream accesses, production,
cleanup, and rollback execution are zero. Rollback is demonstrated by atomic
pre-mutation blocking and preserved base state, not by an authorized reset.

## State transition and non-claims

P14H is accepted only at this isolated multi-stack fixture scope. P14I is the
next stage and remains unauthorized. This evidence does not authorize a real
provider, credential access, downstream repository access, remote PR fixture,
production, cleanup, rollback, P15 entry, or Codex replacement claim.
